# D23: Write timeout

Status: **decided (user, via coordinator)**

**Write timeout** (Finding 2, option (ii-b); generalises D19). A peer that stops reading for good is indistinguishable, through poll and send, from a slow one: a receiver that keeps its window closed while it acknowledges the probes keeps the connection open indefinitely ([T] RFC 1122 §4.2.2.17), so no error is ever reported. So L1 times out every fd, not only hung-up ones: after `pf_sendwait` consecutive rounds with a non-empty outbox and no send progress, L1 drops f's outbox and marks it gone (closed at the reap or the auto-close, as for D19). A round with progress or an empty outbox resets the count. A hard input error (`FReset`) still drops at once (D19 (a)). Model: D19's counters absorbed into one per-fd stall count, `stalls` in the PF state, `stall_step` between the fetch and the reap, now tracking every fd L1 holds (`pf_held`); `pf_hupwait` becomes `pf_sendwait` (8). POLLHUP no longer plays a part. Statements: R1-safe, R1-live and the D16 corollary are unchanged (dropping is the existing `gone` path, which acct already allows as a prefix; nothing on the input side reads `gone`). Output liveness (flush_progress, S4w, flush_live) reads "unless L1 timed f out", an observed disjunct, with a strong form under "the peer reads within `pf_sendwait` rounds of a stall"
