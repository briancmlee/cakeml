# D21: Reset after the peer's EOF

Status: **decided (user, via coordinator)**

**Reset after the peer's EOF** (a Linux conformance finding, P4 and the random test). After the peer's EOF, with an empty inbox and a reset's error pending, recv may return 0 and leave the error pending (`eof_first`), as well as report it. Labelled **[P] POSIX looseness**, consistent with the model's reading of recv's ECONNRESET as the once-reported pending error ([P 2.10.10], [P 2.10.11], [P recv] RETURN VALUE; §4.2). No statement changes: a flushed break read as EOF was already reachable, and the D16 corollary already allows it (`flushed`)
