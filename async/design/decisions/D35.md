# D35: Write timeout in time

Status: **approved (user, via coordinator); not implemented yet**

**Write timeout in time** (design/52, option (C) of moonshot-live's R1; revises D23). A query-only `sys_clock` (empty conf, 8-byte big-endian nanoseconds, no header): C is one `clock_gettime(CLOCK_MONOTONIC)` (die on failure); the model answers `w.ch.now w.hist`, with the rely gaining `now` monotone along the history and `< 256 ** 8` (POSIX: monotonic, cannot be set); no new world state, nothing in l0sys. L1 reads the clock once per round; `stalls` hold each held fd's last-progress time, and an fd is dropped when `now − last ≥ pf_sendtime` (the D23 dropping path otherwise unchanged). The observed excuse becomes `ep_timed_out_t T` (two readings T apart with only out-polls, no send took). New liveness-only hypothesis [F5] in the observed form: a clock read infinitely often has unbounded readings. Busy-polling in stalled rounds is kept (a deadline poll is a separate later decision). Scheduled after echo liveness and the quiet echo, alongside D25's serve-on (D26–D34 are on other branches)
