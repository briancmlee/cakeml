# D20: sys_poll on CakeML's `struct pollfd` buffer

Status: **decided (user, via coordinator)**

**sys_poll on CakeML's `struct pollfd` buffer** (§3.6). The C is a pass-through: `poll` runs in place on the caller's buffer from offset 16, with no copy loop and no cap (`MAX_FDS` 4096 is gone, and with it `poll_chunks`: L1 polls once per round). The layout is a **build-time-checked ABI assumption** (static asserts); a misaligned buffer gets EINVAL (runtime check); events other than POLLIN/POLLOUT are an **unchecked precondition** on callers, which L1 meets (proved). The L0 model reads the entries (`pollfd_entries`), allows fds ≥ 2^31 (revents 0), and has `poll_junk` for a failed poll's revents. Conformance rerun on Linux (§4.3). R1/R1-live are unchanged in wording; internally, `psmall` (polled fds < 2^31) is a new invariant along runs
